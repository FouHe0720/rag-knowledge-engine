# 校园资料检索

这组材料解决的是资料版本容易混淆的问题。材料来自本地山大威海知识库，仓库只保存经过选择的原文段落，不要求克隆者拥有原始目录。

| 材料 | 范围 | 可核对内容 |
|---|---|---|
| 计算机、人工智能培养方案 | 2024版，摘录未明确适用年级 | 学分相同但弹性学制不同 |
| 物理学培养方案 | 2023级 | 179学分、国际学分要求 |
| 智能导航、数据科学、计算法学简章 | 2024级 | 名额、考试、选拔条件各不相同 |
| 选课通知、英语分级测试通知 | 2024级 | 历史选课时间、翻译学院例外、考试证件 |

## 数据如何进入项目

从 DOCX 的 `word/document.xml` 读取 `w:p`，按出现顺序编号，包括表格内和空段落。选中的 `w:t` 拼接后去除首尾空白，写为 Markdown 的“原文第 N 段”小节，再交由现有解析器入库。DOCX 原文件哈希、入选段落和 Markdown 哈希保存在 `datasets/campus/manifest.json`。

`scripts/campus_sources.py` 校验仓库摘录的哈希。提供 `--source-root` 时还会校验原 DOCX 哈希、逐段文本，并重建 Markdown 与仓库文件逐字节比较。本次已对本地 8 个原文件完成此验证。来源文件版权归原作者；摘录未包括个人联系方式、名单或账号。

## 范围在检索前生效

```json
{
  "question": "弹性修业年限",
  "strategy": "bm25",
  "top_k": 3,
  "sources": ["campus/ai-curriculum-2024.md"]
}
```

`sources=null` 表示全部已入库文档；`[]` 表示空范围。未知路径得到空结果，危险路径被拒绝。先从同一快照中筛选 chunk 及对应向量，再构建检索器，避免“先检索后过滤”造成目标文档在候选截断前就被挤掉。原始问题改写后仍使用同一范围。这个参数是资料选择，不是用户访问控制；没有认证与语料 ACL。

## 回归结果的含义

`make campus-demo` 使用单独的数据库，按固定资料范围执行 20 条检查；18 条检查原文段落和关键字段，2 条检查无匹配词、指定2026版资料不存在的拒答。输出记录数据清单哈希、题集哈希及完整候选和引用。它不衡量开放域问答能力，不自动推断用户在自然语言中提到的年份或专业。

浏览器实测完成计算机方案查询、切换人工智能方案查询，分别得到“3至6年”和“4至6年”；390px 窄屏无横向溢出，无页面脚本错误。截图为该次真实运行。

## 仍需处理的问题

词项覆盖不能判断所有语义条件。比如自然语言里问“今年的政策”，服务不会自动验证发布日期，需要调用方明确限定资料并提示历史范围。导航简章里“中午14点”的原文保持不变，应由人工核对，不能擅自改成12点。数据科学摘录未给出固定推免比例，不能借用计算法学的30%。
